# Project content

Project briefs are repository-owned and validated before deployment. Each
published project contains one `project.json`, six stage Markdown files with
one checkpoint configuration per stage, and a separate `reference.md`.

Runtime progress is stored separately from topic progress and references the
stable project and stage keys. Projects do not prescribe a hidden software
sequence. Tool guidance names reasonable options while the learner is assessed
on evidence, validation, and communication.
